# 検証と完成条件

現在の仕様はスクロール初回演出。旧タイマー・全件表示仕様の検証結果は履歴として保存し、今回の合格根拠にはしない。

## 自動検証

- `pnpm run build`：原稿検証・Markdownとメタデータ生成・型検査・本番ビルド。
- `pnpm run lint`：ESLint、TSX/JSXの1関数規約。
- `pnpm run test:content`：C01〜C09。必須項目・全type・安定整列・予約ID・危険URL・画像実在・HTML拒否・公開時mock拒否・失敗時の非ゼロ終了・生成JSONに本文なし・Markdown参照・スキル0〜100検証。
- `pnpm run test:e2e`：下表。StrictModeの開発サーバーとE2E_PREVIEW=1の本番プレビューを区別して実行。

| 条件 | 確認する結果 |
| --- | --- |
| 初期表示 | 名前、全本文、Markdown、スキル値がDOMに存在。削除指定文言なし |
| 初回スクロールと再訪 | 初回のみanimationstart、閲覧済みIDとDOM同一性を保持 |
| B案の固定 | 縦ラインが適用され、比較UIなし。トップにアスタリスクを表示 |
| 演出の開始位置 | カードが画面下端に入っただけではopacity:0を維持し、内側へ入ってから0→1で演出 |
| 目次のスクロール追従 | 下方向・上方向で選択を更新。末尾は最後の項目、先頭は未選択。通常スクロールでURL・履歴を変えない |
| 関連リンク欄 | 1280px未満は非表示、1280px以上は本文の右列。本文の外部リンクは全幅で利用可能 |
| アンカー・初期ハッシュ・履歴 | 対象位置へ移動、ユーザー操作だけ見出しにフォーカス |
| reduceと印刷 | 演出なし、reduce解除後も閲覧済みは再演出なし、印刷で全本文を保持 |
| 320/375/768/1024/1440px | 全体の横はみ出しなし、画像が読み込まれる |

PlaywrightのChromium / Firefox / WebKit、Android相当・iPhone相当で確認する。利用できないエンジンや実機は未確認として理由を残す。エミュレーションを実機確認と表現しない。

ホバーの期待値は画面幅ではなく `(hover: hover)` で分ける。通常リンクはホバー対応環境でopacity:0.8、タッチ環境の疑似マウス移動ではopacity:1を確認する。キーボードのfocus-visibleではどちらも0.8になることを検証し、タッチ環境でもテスト全体をスキップしない。

## 画面・ブラウザーUI

375pxと1440pxの全体・トップ装飾を画像で確認する。縦ラインのスタイルが本番CSSに抽出されていることも確認する。長文・長URL・表・コードはブロック内に収まり、キーボードで横スクロールできること。200%拡大、読み上げ、実タブ復帰、ブラウザーメニューからの検索・印刷は自動イベントと区別する。

画面キャプチャ・PDF・コントラスト・バンドルサイズは `pnpm run measure --screenshots-only`。Lighthouseは `pnpm run measure` で通常/reduce × mobile/desktopを各3回測定して中央値・条件を保存する。MEASURE_URLとMEASURE_OUTで対象を指定し、本番ビルドを測定する。以前のスコアを変更後の実績として流用しない。

## 公開前

本文・スキル数値・実績・画像・リンクを実データへ差し替え、mock:falseとしたbuild:releaseを検証する。GitHub Pagesの実際のbaseで画像・直接ハッシュ・更新・履歴・リンク到達を確認する。公開後の配信性能はローカル実測と分ける。

検証記録は[一覧](verification-results/README.md)を参照。各記録は実施時点の実装に対する結果であり、現在の仕様の代わりにはしない。

追加検証：全aに共通コンポーネントが付くこと、目次リンクだけ下線0→100％、本文・カード・関連リンク・ブランド・フッターは下線なしで400msのopacity変化（1→0.8）、リンク移動直後はscrollYが跳ばず到着後に表示されること、停止ボタンがないこと、読み込みフェード、focusinと検索イベントでの表示救済。遅延画像は読み込み完了を待って判定する。

目次の読み込みanimation-name、選択項目をhoverした後の実際の色、トップのborder-bottomと32pxのmargin-bottomをE2Eで検証する。スタイル移動後もカード・リンク・reduce・幅別表示を再確認する。

Tailwind移行時は依存・設定・CI・生成物に旧スタイル処理が残らないことを確認する。スタイルのcodegenなしでbuild・dev・型検査が実行でき、既存の表示・動作テストが通ること。
